# CyberDefenseVR

Educational VR cybersecurity training simulator (Unity 6, URP, OpenXR, Meta Quest target).
A fictional, purely visual attack travels attacker -> router -> protected server; the player raises a firewall shield to block it.
No real networking, malware or attack functionality exists in this project.

## IMPORTANT: current status (read first)
This archive was produced in an environment **without the Unity Editor**. Therefore:
- Scripts and Editor tools were written but **never compiled or run**.
- **Scenes, prefabs and materials are NOT in the archive.** They are generated by an Editor script the first time you open the project.
- No APK was built. Nothing was tested on a headset. See TESTING_REPORT.md.
Expect to fix a small number of compile errors on first open (package API versions could not be verified offline).

## If the project opens empty (only Main Camera + Directional Light)
Run **CyberDefense > Diagnose Project**. Typical causes: (a) the outer folder was opened instead of the one containing Assets/Packages/ProjectSettings; (b) red compile errors in the Console block the generator; (c) the generator dialog was dismissed -> run **CyberDefense > Generate Project Assets**.
See START_HERE.txt.

## Requirements
- Unity 6.3 LTS (6000.3.22f1 requested; any 6000.x should work, edit Packages/manifest.json if a package version is not found).
- Android Build Support (+ OpenJDK, Android SDK & NDK) for Quest builds.
- Packages in Packages/manifest.json: Input System 1.14.0, URP 17.3.0, UGUI 2.0.0 (TextMeshPro) + built-in modules. These pins could not be checked against the registry offline; if Package Manager reports a missing version, set it to the version Unity suggests.
- XR Management, OpenXR and Unity OpenXR: Meta are installed BY NAME by the generator (Package Manager picks the versions verified for your editor; needs internet). They are not pinned in the manifest on purpose.

## Open the project
1. Unity Hub > Add > select the `CyberDefenseVR` folder > open with Unity 6.
2. Let packages import. A dialog may offer to enable the new Input System backend: accept (editor restarts).
3. On first open a dialog offers to run the generator (menu **CyberDefense > Generate Project Assets** to run it manually).
   It imports TMP Essentials, creates materials, prefabs and three scenes, configures URP, Android player settings and Build Settings.
4. Run **CyberDefense > Validate Project** (writes ValidationReport.txt).

## Headless generation (optional)
`UNITY=/path/to/Unity ./generate_assets.sh` (or `generate_assets.bat`). Runs the same generator in batch mode, installs XR packages if needed (exit code 2 = rerun, the script does this), writes generate_*.log and ValidationReport.txt. Do not add -quit.

## Run on desktop
Open `Assets/Scenes/MainMenu.unity` and press Play, click **Desktop Test** (or open `DesktopTest.unity` directly).
Click buttons with the mouse; hold the right mouse button and drag to look around.
To run the automatic attack/defend/reset cycle test: in DesktopTest select `SelfTest`, tick **Run On Start**, press Play, read the Console.

## Enable OpenXR (one-time manual step)
Edit > Project Settings > XR Plug-in Management > Android tab: tick **OpenXR**.
OpenXR > Enabled Interaction Profiles: add **Oculus Touch Controller Profile**. Enable **Meta Quest Support** feature if listed.
(Also tick the PC tab if you want to test with a PC-connected Quest/Link.) Not automated because the XR settings API could not be validated offline. Also check on first headset run that the camera height is correct (tracking origin mode is left to the OpenXR runtime default).

## Build the APK
File > Build Profiles > Android > Switch Platform; scenes list is preset (MainMenu, CyberDefenseTraining, DesktopTest).
Build. Requires Android module installed. Sign with your own keystore (Player Settings > Publishing Settings) for distribution.
Preset: IL2CPP, ARM64, min API 29, target API automatic, Vulkan then OpenGLES3, package `com.cyberdefense.vr`.

## Install on a Quest
Enable Developer Mode (Meta Horizon app), connect USB, `adb install -r CyberDefenseVR.apk`, launch from Unknown Sources.

## Controls
Aim with the dominant-hand controller (Settings > Dominant Hand), pull the trigger on a button. Press and release on the same button to click.

## Architecture
- XR: plain XR rig hierarchy (no XR Origin component, to avoid an unverifiable package dependency) + OpenXR; head/controller poses read through Input System actions (VRRigDriver).
- UI pointer: custom `VRUIPointer` (ray vs world-space canvas, Button events). XR Interaction Toolkit is intentionally NOT used, to avoid mixed frameworks and unverifiable API surface.
- Gameplay: `SimulationController` state machine (Ready, Attacking, Defending, AttackBlocked, AttackSuccessful, Resetting), `AttackController`, `DefenseController`, `NetworkNode/Connection`, `ThreatIndicator`, `DashboardController`.
- Audio: synthesised tones (no audio files); volumes in Settings.

## Known limitations
See TESTING_REPORT.md. Notably: ray uses pointer pose if exposed, else grip pose (tune `gripToAimPitch`); no hand tracking or passthrough; no haptics; visuals are primitives; performance unprofiled.

## Troubleshooting
- Pink materials: URP asset not assigned -> run generator again.
- Text missing/squares: Window > TextMeshPro > Import TMP Essential Resources.
- Black screen in headset: confirm OpenXR enabled for Android, single camera, URP asset assigned.
- Buttons ignore the controller: check XR Management OpenXR + Touch profile; trigger bindings use `<XRController>{Hand}/triggerPressed`.
- Compile error about an API: check package versions in Package Manager vs manifest.
